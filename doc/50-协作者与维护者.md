## 协作者与维护者

想要达到最理想的维护状态，每一个 recipe 都需要有专人长时间维护。**我们的代码里使用了 recipe (某个菜的烹饪方法) 这个词，因而整个项目便和 "饮食" 有关，比如 `menu`: 汇集了所有的 dish 的菜单。因此，我们的维护者和贡献者身份依然使用了这个惯例：**

1. **Chef**

    主厨: 一个 recipe 的主要作者

2. **Saucier**

    调味：一个 recipe 的次要贡献者

<br>



## 第一次贡献者

### 注册身份信息

在 `src/chsrc-main.c` 的 `chsrc_register_contributors()` 函数里，在最后（我们按参与本项目的时间顺序排列）添加一行：

```c
chef_register_contributor ("@ID: 你的GitHub/Gitee用户名或任意不与其他贡献者冲突的名字",
  "你的真实姓名",
  "你的邮箱地址",
  "若 chsrc ls <recipe> 的时候不想使用真实姓名，可以用这个参数的字符串来代替");
```


### 更新 Recipe 信息

在你修改的 recipe 文件的 `_prepare()` 函数里，需要做以下更新：

1. **更新 recipe 修改时间**（每次修改 recipe 代码都要更新）：
   ```c
   chef_set_recipe_last_updated (this, "YYYY-MM-DD");
   ```

2. **更新镜像源信息时间**（仅当你修改了镜像源列表时才更新）：
   ```c
   chef_set_sources_last_updated (this, "YYYY-MM-DD");
   ```

3. **将自己加入 `sauciers`**（次要贡献者列表，将计数加一并添加自己的 `@ID`）：
   ```c
   // 原来是 0 个 saucier：
   chef_set_sauciers (this, 0);
   // 改为添加你自己：
   chef_set_sauciers (this, 1, "@你刚注册的ID");

   // 原来已有 1 个 saucier：
   chef_set_sauciers (this, 1, "@Someone");
   // 改为添加你自己：
   chef_set_sauciers (this, 2, "@Someone", "@你刚注册的ID");
   ```

4. **验证上述信息正确**

   ```sh
   # 应当能看到你的信息
   ./chsrc ls <recipe>
   ```
